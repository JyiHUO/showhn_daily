### 4.Rocky: Rust SQL Pipeline 基因引擎

![Rocky: Rust SQL Pipeline 基因引擎](https://showhntoday.com/images/47935246.png)

**URL：** [https://github.com/rocky-data/rocky](https://github.com/rocky-data/rocky)

**作者：** hugocorreia90

**描述：**
Rocky 是一个基于 Rust 语言构建的 SQL 数据管道控制平面。它不替换你现有的数据仓库（如 Databricks 或 Snowflake），而是负责管理数据管道的“大脑”——依赖关系、数据变更、执行逻辑、成本、数据血缘以及合规性。它的创新之处在于提供了类似 Git 的工作流（分支、回放）、代码编译时就实现的列级别数据血缘追踪，以及将数据治理（如数据分类、隐私掩码）内置于管道设计中的能力，从而让数据团队能更高效、更安全地管理和理解他们的数据资产。

**如何使用：**
开发者可以将 Rocky 集成到他们现有的数据工作流中。它可以通过命令行工具（CLI）或者 VS Code 插件来使用。对于数据仓库，Rocky 可以通过适配器（如 Databricks、Snowflake、BigQuery）与其连接。开发者可以通过编写 `rocky.toml` 配置文件来定义数据管道的依赖关系、执行逻辑以及治理策略。例如，你可以使用 `rocky branch create <branch_name>` 来创建一个数据管道的分支，就像 Git 的分支一样，用于独立开发或测试。使用 `rocky replay <run_id>` 可以重现某个特定运行时的 SQL 执行过程。VS Code 插件可以通过 Language Server Protocol (LSP) 在你编写 SQL 代码时，实时显示列级别的数据血缘信息，以及潜在的风险（如数据扩散）。你可以利用 `rocky compliance` 命令来检查数据管道是否符合预设的合规性要求，并将这个检查集成到 CI/CD（持续集成/持续部署）流程中，确保只有合规的代码才能上线。所以，对于开发者来说，Rocky 提供了一种更直观、更安全、更高效的方式来构建和管理数据管道，将复杂的数据治理和版本控制融入日常开发流程。

### 7.LavinMQ: 精悍消息中间件

![LavinMQ: 精悍消息中间件](https://showhntoday.com/images/47933145.png)

**URL：** [https://github.com/cloudamqp/lavinmq](https://github.com/cloudamqp/lavinmq)

**作者：** CarlHoerberg

**描述：**
LavinMQ 是一款轻量级的开源消息中间件，它用 Crystal 语言编写，旨在以极低的资源消耗提供强大的消息处理能力。它支持 AMQP 0-9-1、MQTT、HTTP 和流式传输等多种协议，并且可以在非常有限的硬件资源下运行，例如在仅有 1GB 内存的服务器上就能达到每秒处理数十万条消息的性能。它的核心创新在于通过内存映射文件和仅追加写的方式，最大限度地减少内存拷贝、分配和系统调用，实现了高效可靠的消息存储和传输。

**如何使用：**
开发者可以使用 Docker 轻松启动 LavinMQ。例如，运行 `docker run -p 15672:15672 -p 5672:5672 cloudamqp/lavinmq` 命令后，LavinMQ 就会在你的本地运行，并监听 15672（通常是管理界面端口）和 5672（AMQP 协议端口）。之后，你的应用程序可以通过标准协议（如 AMQP）连接到 LavinMQ，发送和接收消息。对于需要消息持久化（即消息不会因为重启而丢失）的应用，LavinMQ 会将消息高效地存储在磁盘上。它还可以集成到现有的微服务架构中，作为不同服务之间进行异步通信的桥梁，解耦服务间的依赖。
